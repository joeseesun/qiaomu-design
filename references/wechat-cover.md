# 微信公众号封面：先保证方图，再展开横图

适用：创作或修改公众号封面、公号头图、微信文章封面。先读文章或用户给的摘要与参考图，提炼一个主题和一句封面标题；只缺次要信息时直接判断，不反复询问。

## 双比例与中央安全区

- 横版大图按 2.35:1 设计；常用参考尺寸为 900×383，制作可用约 1920×817 的高清画布。方形小图按 1:1 核对。
- 后台可调整裁切位置，不把“所有场景永远自动取正中”当作平台事实。默认按居中方形安全区设计，可减少上传后手调；用户指定其他裁切位置时按指定区域检查。
- 原图宽 W、高 H，居中正方形范围为 `x=(W-H)/2 .. (W+H)/2`，纵向使用完整高度。横图比例 2.35:1 时，安全区占原宽约 42.6%，约为横向 28.7%–71.3%。这来自几何推导，不是平台额外规定。
- 品牌/主标题和关键主体的完整轮廓应共同落在该区内，并再留一圈内边距。两侧用于背景、光影、纹理与非必要装饰；别让识别主题所必需的信息只在两侧出现。
- 先把中央方图当成完整独立封面，再向两边扩展横图。不要直接沿用“标题左、主体右”的网页 Hero 排法：两边各自好看，正中裁切可能两边都丢。
- 核心标题可以分行，例如 `TRAE` / `全面升级`；副标题按必要性取舍，不能靠小字、署名或边缘标注解释主视觉。标题必须能在缩略尺寸下辨认。

## 设计与迭代

1. 从文章选一个可辨认的视觉隐喻；短标题、大字重、明确前后景和单一焦点优先于堆功能点。检查中文错字、字形变形、断句与品牌拼写。
2. 有用户认可的参考时，明确“保留 / 重做 / 必须满足”：例如保留背景色与空间感，重做主体，标题和主体兼容方形裁切。不要把局部修改变成完全换风格。
3. 缩略图中有意义的主体优先。人物、门户、漂浮纸片、复杂场景和微小标签仅在传达主题时使用；不要自动塞入“人物走进发光门”的通用 AI 隐喻。
4. 多方向默认给四张，当前用户明确数量则照做。初次探索可改变媒介、构图和隐喻；用户已选背景或风格后，在该范围内通过主体形态、材质、光影与层次发散，不为凑差异强行换色。
5. 蓝绿、玻璃材质、台阶和中央雕塑是 2026-10-09 TRAE 案例的选择，不是公众号封面的通用偏好。居中是双比例适配策略，不要求每次都机械对称。
6. 用实际生成模型产出图片；用户要求内置模型时使用内置图像生成工具，不能悄悄换外部模型或用 HTML/SVG 占位冒充成图。编辑参考图前先查看它，并通过可用工具的参考图参数传入。
7. 用户只要候选时，生成、核对并交付候选就是本次结果；用户选定后再按要求精修。不要把等待选择变成不交付图片，也不要自行替用户发布或更换文章封面。

## 生图提示词骨架

按目标画布调整坐标。以下是约 1920×817 的示例，不应无视模型实际输出尺寸硬套：

```text
用途：微信公众号文章封面，横版约 2.35:1。
文章主题：〈一个准确主题〉。
参考图：保留〈背景/配色/空间/质感〉；重做〈主体/文字/构图〉。
中央正方形约 x=552..1369。主标题和完整核心主体都在这个范围内，并留内边距。
中央方图裁切后必须是一张完整独立封面。两侧只延展背景，不放必要文字。
文字逐字：〈短标题，可分行〉；副标题：〈有必要才加〉。
主视觉：〈单一主题隐喻〉，文字与主体不互相遮挡，缩小后仍可识别。
避免：〈本轮具体反目标〉。不输出裁切参考线、随机小字或水印。
```

不要只写“重要信息在中央 80%”：在 2.35:1 横图里，80% 仍远大于居中方图能保留的宽度。

## 验收与交付

- 每张查看真实生成结果，不能用提示词中的要求代替验收。按实际 W/H 计算方形区域。
- 同时查看横图、居中 1:1 和约 64–96px 方形缩略预览；主标题与主体均保留，无截字、遮挡或主体不明。副标题在极小图中可退居次要，关键品牌/主标题不能依赖它。
- 多方案交付编号清晰的原图，并附同页横图/方图对照，或提供可直接查看的等价预览。预览页只是呈现和裁切检查，不代替生成图片。
- 可以用 `object-fit: cover; object-position: center; aspect-ratio: 1` 制作显示裁切预览，保留原图；若用户要正式方图文件，按图像工具权限与用户要求导出，并与预览核对。
- 候选和最终图片保存到用户指定目录或当前工作区，保留旧版本。交付可点击路径；推荐说明聚焦主题贴合度、缩略辨识度与双比例表现，不声称已上传或已发布。
- 不使用 Computer Use 或其他 UI 自动化操作用户微信客户端及微信内嵌页面。封面创作与本地预览不需要操作微信；后台裁切或发布由用户自行完成。

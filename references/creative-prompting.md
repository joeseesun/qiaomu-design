# 创意提示词编排：Discover → Define → Deliver

用于开放式设计、多个视觉方向、方向深化和最终视觉打磨。它补充现有三阶段流程，不替代功能契约、
用户偏好、项目设计系统、工程检查或真实浏览器验收。

来源边界：本规范吸收 Anshu Chimala 在 Lenny's Newsletter 文章公开部分中的 Technique 1–6，
以及 Sakana AI 的 String Seed of Thought（SSoT）研究。文章从 Technique 7 起属于付费内容，
本规范没有猜测或转述未读取部分。

## 何时使用

- 使用：开放式落地页、品牌页、作品集、活动页、创意 404、多方向探索、已有方向仍显模板化。
- 不使用创意种子：像素复刻、严格遵循既有 DESIGN.md、修 bug、可访问性整改、事实检索、只有一个正确答案的任务。
- 功能型页面可以借用 brief 与评审方法，但创意种子只能影响表现层，不能改变既有心智模型和任务流。

## 1. Discover：先拓宽，再收敛

### 1.1 为开放方向注入外部差异

“大胆一点”不是随机机制。需要多个方向时，为每个方向生成不同的长随机字符串，作为私有创意种子；
优先使用系统熵源，工具不可用时再让模型内部生成。不要把种子显示在页面、文案或最终设计中。
Unix 环境可用 `openssl rand -hex 24` 生成；把种子记在内部工作笔记以便复现，但不作为产品内容。

把种子分段映射到至少四条决策轴，而不是从字符串联想一个表面隐喻：

- 媒介或时代：印刷目录、剧场布景、工业仪表、博物馆标签、街头导视、早期数字设备等
- 构图：对称 / 非对称、中心 / 边缘、连续叙事 / 离散模块、静态 / 空间纵深
- 材质：纸张、金属、织物、玻璃、墨水、像素、摄影、3D 或纯排版
- 字体与节奏：字族角色、字阶跨度、留白压力、信息密度、数字与正文的关系
- 交互与动效：一个签名动作、反馈频率、物理感或完全静态

每个方向同时分配一条互斥硬约束。种子负责打破模型默认分布，硬约束负责让方向能被解释和复现。
任何种子结论都必须经过设计判断；若损害功能契约、品牌、可读性、无障碍或性能，直接丢弃。

### 1.2 用“雄心命题”代替风格形容词

不要只写“高级、独特、极简”。从一个非软件世界借视觉语言，并说明它如何改变页面：

```text
让每个 section 像一张可连续阅读的博物馆展签，但仍完成落地页的比较、信任与转化任务。
借用的是编辑节奏、材质和观看距离，不复制任何现成品牌或作品。
```

一个有效命题应同时说明：想制造的情绪、借用的世界、转译机制、必须完成的产品任务，以及哪种俗套
最容易把它做坏。

### 1.3 人的反应是方向数据

按以下顺序收敛，不要把 AI 灵感原样复制回下一轮：

1. 先列 12–20 个短而宽的方向名，每个只写一句，不深入实现。
2. 选择差异最大的 4 个做真实 mini mockup。
3. 记录用户对样机的自然反应，整理为“想要 / 不要 / 必须保留的张力”。
4. 让模型根据这些反应锐化方向，直到用户能说清为什么选它。
5. 最后才编译简洁的 build brief。

## 2. Define：把方向变成可执行身份

### 2.1 Build brief 编译器

方向确认后，用下面结构生成短 brief；不写散文，不塞实现教程：

```text
产品与受众：
功能契约：存在理由 / 3 秒必得信息 / 必须完成的动作
目标情绪：希望用户先感到什么，再理解什么
灵感转译：借什么世界；具体转成哪些构图、材质、字体和交互规则；明确不复制
创意决策：种子导出的 3–5 个有效决定 + 互斥硬约束
签名动作：一个最值得记住的视觉或交互动作
反目标：3–5 个最可能出现的模板化或过度设计结果
资产策略：真实图片 / 生成图 / 3D / 视频 / 纯排版；选择理由与降级方案
实现边界：既有组件、性能、响应式、无障碍、内容与品牌约束
验收：可观察、可截图、可操作的通过条件
```

### 2.2 独立视觉批评回路

当用户明确要求 subagent / 并行评审，或当前工作流已允许独立评审时，让批评者只看当前桌面与移动端
截图、目标气质和可选参考基线；不要给代码、实现难度、先前理由、旧评分或上一轮批评。新上下文能减少
沉没成本和自我辩护。

批评者使用固定提示词：

```text
把目标气质想象成一流设计工作室的成品标准。只根据截图评审，不推测代码。
同时检查整体构图与细节工艺；惩罚过度使用、过量或明显 AI 模板化的模式。
如有参考图，把它们当质量与气氛基线，不当临摹目标。
输出：1) 最强的一点；2) 最大的三个差距，按影响排序并具体到区域；
3) 0–10 分的接近程度；4) 下一轮只改哪三件事。保持直接、具体、有立场。
```

质量基线尽量视觉化：把当前截图与 2–4 个专业参考并列比较或排序，比“漂亮吗”更客观。参考只用于
校准 polish 和 taste，不得要求复制。

每轮使用同一份批评提示词，只更换当前截图和参考基线。停止条件：默认最多两轮“截图 → 批评 → 修正”。达到 9/10 可停止；两轮后仍未达标则先判断是否收敛，
向用户报告剩余差距或更换方向，不得无限循环消耗时间与 token。评分不替代功能测试和人工判断。

## 3. 媒体资产：需要时主动调用，不为炫技调用

编码代理容易用渐变、几何形状和 CSS 纹理代替真正的视觉资产。若方向的个性依赖人物、物件、材质、
空间或叙事画面，应主动评估图像生成或真实素材，而不是默认画几个发光圆。

- 图像：先写清构图角色、材质、光线、留白位置、色彩关系与 UI 叠放方式；生成后把最终资产放进项目，
  记录来源/生成方式，检查裁切、响应式、加载与文字对比度。
- 视频：只在复杂物理运动、循环视觉或关键状态间插值确实能提升体验时考虑。先定义首尾关键帧、循环点、
  透明/抠像方案、静态 poster、压缩预算和 reduced-motion 降级；逐帧或慢放检查接缝、背景、闪烁和文本遮挡。
- 模型和服务会变化，使用前核验当前能力、价格和许可。不要把 API key 写进提示词、Skill、代码、日志或交付物；
  凭据只放受保护的本地环境或密钥存储，并遵循当前任务授权。

若媒体资产不增加信息、情绪或品牌识别，就不用。纯排版方向也可以成立，但必须是主动判断，不是代理偷懒。

## 4. Deliver：最后一轮专门做减法

实现完成后，不要只问“还能加什么”，逐项问“删掉会损失什么”：

| 元素 | 保留条件 |
|---|---|
| 标签或说明 | 没有它，用户会误解信息或下一步 |
| 容器或卡片 | 它表达真实分组、层级或交互边界 |
| 颜色或高亮 | 它编码状态、优先级、品牌或明确焦点 |
| 动效 | 它解释因果、空间关系、状态变化或即时反馈 |
| 自定义控件 | 它比平台原生/项目现有组件更清楚、更可用 |
| 留白 | 它建立节奏、分组或观看距离，不是空洞 |

删除重复标签、重复 CTA、无语义容器、随机颜色、装饰性 glow、系统自言自语和比原生组件更差的自定义控件。
做完减法后重新截图，确认功能契约仍完整，视觉焦点更清楚，信息密度不是靠删字假装极简。
